# Frontend Lab — Workflow

## Regra

Um laboratório por vez.

Não avançar automaticamente enquanto o conceito principal não estiver entendido.

## Etapa 1 — Briefing

Claude deve explicar:

- objetivo
- conceito
- biblioteca
- resultado esperado
- restrições

## Etapa 2 — Perguntas

Claude deve fazer algumas perguntas para verificar o conhecimento atual.

## Etapa 3 — Desafio

Definir um desafio pequeno e concreto.

O desafio deve ser possível de implementar sem gerar dezenas de arquivos.

## Etapa 4 — Implementação

O usuário implementa.

Claude não deve assumir a autoria da implementação.

## Etapa 5 — Review

Avaliar:

- TypeScript
- React
- Next.js
- biblioteca estudada
- arquitetura
- performance
- acessibilidade
- qualidade visual

## Etapa 6 — QA

Testar:

- desktop
- mobile
- resize
- interação
- navegação
- estados
- reduced motion
- console
- hydration

## Etapa 7 — Comparação

Quando existir uma biblioteca concorrente, discutir:

- API
- DX
- flexibilidade
- controle
- performance
- complexidade
- caso de uso

## Etapa 8 — Registro

Registrar:

- o que aprendi
- o que achei difícil
- o que funcionou
- o que não funcionou
- quando usaria
- quando evitaria

## Etapa 9 — Score

Atualizar o nível:

### 0 — Nunca usei
Não conhece a biblioteca.

### 1 — Conheço
Entende o propósito e viu exemplos.

### 2 — Consigo usar
Consegue criar experimentos seguindo documentação.

### 3 — Consigo integrar
Consegue integrar ao Next.js sem tutorial passo a passo.

### 4 — Consigo resolver problemas
Consegue diagnosticar problemas e fazer escolhas.

### 5 — Domino
Consegue explicar, implementar, otimizar e comparar.

## Regra de código

Código sem comentários.

Nunca inserir comentários no código, mesmo quando eles parecerem úteis.

Explicações devem ficar fora do código.
